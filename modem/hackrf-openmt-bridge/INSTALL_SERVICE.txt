HackRF bridge as a service
Created by Rick KD0OSS

  sudo apt install libhackrf-dev cmake pkg-config libmariadb-dev      (once)
  cd modem/hackrf-openmt-bridge && mkdir -p build && cd build && cmake .. && make
  sudo cp ../hackrf-bridge.service /etc/systemd/system/        (edit paths and options first)
  sudo mkdir -p /etc/systemd/system/modem-host.service.d
  sudo cp ../modem-host.service.d/hackrf.conf /etc/systemd/system/modem-host.service.d/
  sudo systemctl daemon-reload
  sudo systemctl enable --now hackrf-bridge
  mysql -u root -p modem_host < db/openmt.sql (adds the bridge to the dashboard Services tab)

Check:  journalctl -u hackrf-bridge -f      (shows "settings changed", "RX gains", and the HackRF start)
        hackrf_info                         (the HackRF must be found before the bridge can start)

Settings: the bridge keeps its settings (rxFrequency, txFrequency, rxLnaGain, rxPgaGain, txDacGain,
rxLevel, freqOffsetPpm, rxInvert, txInvert, mode) in the config database and shows them in the Modem
tab of the dashboard. It creates any that are missing, using the command line options as the defaults,
and the saved values win from then on (so editing --lna-gain etc. in the service file no longer changes
a saved setting). When you save the Modem tab the modem host tells the bridge, which reads them again and
retunes the receiver at once. Use --modem-name for a modem name other than modem1.

Setting the RX level: add --rx-stats to ExecStart for a while (then systemctl daemon-reload and restart),
key a radio and read the "rx level" and "rx frequency error" lines in the journal; see the README.

The bridge publishes streamType (SAMPLE) and bridgePort (the name of the --pty-symlink path below /dev,
hackrf-modem by default); the modem host connects to that port by itself. Restart the modem host after the
bridge is restarted, since the modem host opens the bridge's PTY when it starts. Do not run two bridges
for the same modem name, and do not run a protocol service and OpenMT Radio for the same mode at once.

Running as the pi user instead of root: install the HackRF udev rules (53-hackrf.rules, shipped with
libhackrf), add the user to plugdev, set User=pi and a --pty-symlink below /run.
